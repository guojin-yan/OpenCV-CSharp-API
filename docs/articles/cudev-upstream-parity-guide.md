# Cudev source callable inventory and partial parser map

Cudev is OpenCV's CUDA device layer. This evidence inventories all 76 installed `.hpp` files from pinned OpenCV contrib 5.0.0, including component and detail headers. It records a partial parser map and 5,433 source function declaration occurrences, including class-template members and finite local declaration macro expansions. Counts retain repeated declarations, private/detail members and inactive branches; they are not distinct usable APIs or wrapper implementations. Complete callable/instantiation coverage remains open.

The pinned OpenCV `hdr_parser.py` deliberately skips statements beginning with `template` and does not expand declaration macros. Its 144 emitted declarations comprise 110 callables, 24 classes/structs and ten enums under the recorded CUDA source configuration. All 110 callable identities reconcile to the source syntax inventory. Every emitted callable is intentionally omitted because this package has no Cudev native ABI entrypoint or managed wrapper. Zero unexplained missing declarations applies to this parser subset.

## Template and macro evidence

The lexical extractor uses Python's standard library and the pinned OpenCV parser. `source_inventory.py` scans every installed header with all preprocessor branches retained. It masks comments and literals, removes logical directive lines from declaration discovery, balances template parameter lists and declaration bodies, and records exact source positions and SHA256 values. It distinguishes template-template parameters from declarations and preserves nested template declarations inside class bodies.

| Source unit | Count | Meaning |
| --- | ---: | --- |
| Direct template declarations | 1,100 | 454 class/struct templates and 646 function templates, including forward declarations and specializations |
| Template-template parameters | 11 | Nested template parameter lists, associated with their enclosing declaration |
| Function-like macro definitions | 49 | Full replacement text, parameters, source positions and conditional context |
| Macro invocations | 1,206 | Source arguments and references to named source definitions |
| Conditional directives | 397 | Every `if`/`ifdef`/`ifndef`/`elif`/`else`/`endif`, including header guards |
| Template keywords within macro bodies | 92 | Counted inside the 49 definitions, separately from direct declarations |

The 1,100 direct declarations, 11 template-template parameters and 92 macro-body template keywords reconcile all 1,203 `template <` tokens outside comments and literals. Counts retain inactive branches. Source units overlap: a class-template span can contain member templates or macro invocations, and one macro definition can be invoked repeatedly. These counts must not be added to the parser's callable count or interpreted as concrete template instantiations.

Coordinates use UTF-8 source normalized to LF, zero-based Unicode offsets with an exclusive end, and one-based line numbers. A macro invocation's definition references are lexical name references across the installed source inventory; they do not assert that a definition is active in every configuration. The inventory performs no macro expansion.

The lexical file keeps `macroExpansionClaimed=false`. Its linked `sourceCallableInventory` binds a separate, narrower local expansion claim and its exact bytes/counts. The hash chain is catalog → lexical inventory → source callable inventory; raw and summary also bind the lexical file.

## Expanded source callable evidence

`extract_source_callables.py` uses tree-sitter 0.25.2 and the C++ grammar 0.23.4 (language ABI 14). It expands 44 local declaration generators using recorded replacements, argument-token substitution and token pasting. The five runtime/expression aliases `CV_CUDEV_SAFE_CALL`, `CV_CUDEV_DESCALE`, `__shfl`, `__shfl_xor` and `__shfl_down` remain unexpanded. Generator calls require one same-header source definition and the audited simple argument form; ambiguous, overlapping or unsupported expansions fail generation. An expansion can generate only a type/trait/derived wrapper with no function at that location.

| Source callable partition | Count |
| --- | ---: |
| Direct source declarations | 1,096 |
| Declarations generated by local macros | 4,337 |
| Total source declaration occurrences | 5,433 |
| Occurrences in a template context (overlapping partition) | 1,979 |
| Definitions, including explicitly defaulted/deleted functions | 5,382 |
| Declarations without a definition at that occurrence | 51 |
| Expanded local declaration macro invocations | 1,088 |
| Expansions with no function declared at that location | 213 |
| Reconciled pinned-parser callable identities | 110 |

Each callable retains its qualified source name, declaration head/hash, declarator, parameter-list entry count, variadic flag, CUDA attributes, access, nested namespace/class/template context and conditional provenance. An ellipsis counts as one syntactic parameter entry; the count is not a permitted call-argument range. Context and parameter byte witnesses allow the .NET guard to check metadata against reconstructed source. Direct origins use LF-normalized Unicode offsets; macro origins use UTF-8 byte offsets inside their independently reconstructed expansion. All expanded CST coordinates use UTF-8 bytes with exclusive ends. Constructor initializer lists and function bodies are outside declaration heads.

The extractor audits every function declarator outside bodies and type aliases. Its 5,417 ordinary function declarators plus 16 conversion declarators reconcile exactly to 5,433 occurrences. The 27 function declarator nodes and 12 abstract function declarator nodes inside bodies are separate syntax roles, not additional APIs. No inherited or implicit functions are synthesized. Imported `using` targets, external macro/include closure, concrete instantiations and C++ type checking remain outside the inventory.

Declaration syntax has zero error/missing nodes. Function bodies retain 28 diagnostics: 27 missing identifiers at CUDA `<<<...>>>` launch expressions and one `ERROR` token at `texture->operator bool()` in `ptr2d/texture.hpp`. Their exact positions, text, context and hashes are preserved. This does not claim error-free body parsing, a valid CUDA build or device execution. Complete callable mapping and MAP-005 remain open.

## Parser normalization

CUDA attribute words are removed only in temporary parser copies. The original installed-header paths and hashes remain the evidence sources. Static and const qualifiers and conversion/call operators remain in the parser metadata.

For the CST, attributes are blanked without moving bytes. Two equivalent non-callable trait expressions in `util/detail/type_traits.hpp` and `util/type_traits.hpp` are parenthesized/cast-normalized to avoid grammar ambiguity, also preserving byte length. Four external namespace markers (`_CCCL_*NAMESPACE_CUDA_STD` and `_LIBCUDACXX_*NAMESPACE_STD`) are blanked only in the tuple-trait tail of `ptr2d/zip.hpp`, around specializations with no callables. This does not assign external-library namespace ownership or establish external declaration closure. Non-attribute normalizations are recorded per header.

The pinned parser first computes namespace-scope static function names through a different path from its non-wrapper argument parser. This contaminates 13 names with their return type, for example `cv.cudev.color_cvt_detail.int LabCbrt_b`. The extractor records each repair and restores `cv.cudev.color_cvt_detail.LabCbrt_b` while preserving `/S`. It does not remove `static` from the source or discard these declarations. Exact parser identities remain unique.

## Build and configuration boundaries

The module's CMake file disables Cudev unless `HAVE_CUDA` is true. It recursively includes the component/detail headers in the module header list, includes OpenCV core, and adds its tests only when `BUILD_TESTS` is enabled and `BUILD_opencv_world` is disabled. The umbrella is not used to shrink the recursive installed-header inventory.

The recorded parser configuration uses CUDA 12.4 source definitions and source architecture 750. Five direct-header probes vary `CV_CUDEV_ARCH` over 0, 120, 200, 300 and 750. `warp/shuffle.hpp` emits 0/0/0/25/25 declarations respectively; `util/atomic.hpp` and `util/simd_functions.hpp` emit 12 and 38 in each probe. These are parser visibility results. The source inventory separately retains architecture gates, the `__CUDACC_VER_MAJOR__ >= 9` shuffle compatibility branches and the `CUDART_VERSION < 12040` tuple branches even where the non-template parser count does not change.

Architecture zero simulates NVCC's host pass with `__CUDACC__` still defined. None of the configurations is a compiler, linking, GPU, driver or runtime test. The package claims no Cudev runtime support. Three dependency records cover the external CUDA toolkit/runtime, Thrust and other external templates, and caller-owned device memory/GpuMat/Stream plus NVIDIA device/driver execution.

## Verification

`Test-CudevUpstreamMap.ps1` independently reconstructs source token discovery and conditional context in .NET, so checked-in evidence can be validated without Python, parser downloads or CUDA. It checks all 76 header hashes/partitions, every lexical span/hash/line/head, template-template parent links, macro definitions/arguments/references, conditionals, static-name repairs, architecture probes, omissions, build gates and empty wrapper evidence. `Test-CudevSourceCallables.ps1` independently expands all 1,088 generator calls and checks normalized input hashes, every callable head/origin/hash, namespace/class/template witnesses, access/arity/CUDA metadata, syntax partitions, all 110 parser reconciliations and the 28 retained body diagnostics.

Twenty-eight real negative fixtures comprise the earlier 16 lexical/parser cases and 12 source-callable cases. They reject missing declarations/expansions, damaged heads/origins, false owners/templates/access/arity, corrupted parser reconciliation, hidden body diagnostics and false concrete-instantiation claims, as well as the earlier wrapper/build/coverage violations. Generation also runs focused regressions for reference returns, constructors, defaulted/deleted functions, operators/conversions (including class-external definitions), nested templates, function-pointer types, macro pasting/branches, Unicode provenance and malformed declarations/arguments.

```powershell
pwsh -NoProfile -File .\scripts\Test-CudevUpstreamMap.ps1
pwsh -NoProfile -File .\scripts\Generate-CudevUpstreamMap.ps1 -PythonPath <python-executable>
# Reuse an isolated target, including for offline regeneration:
pwsh -NoProfile -File .\scripts\Generate-CudevUpstreamMap.ps1 -PythonPath <python-executable> -SyntaxParserRoot <isolated-target>
```

Generation bootstraps tool dependencies into ignored `artifacts/tools/cudev-syntax/`, keyed by Python platform and the requirements hash. Exact releases use official PyPI wheel SHA256 values and `--require-hashes --no-deps --only-binary=:all:`. No global Python or C# package/runtime dependency is added. Hosts without a compatible wheel fail generation; invariant checks do not bootstrap tools.

The catalog, source-evidence initializer, ledger and release closeout bind all seven Cudev artifacts, extractors/tests, pinned requirements, bootstrap and .NET guards. The second Cudev phase adds one ledger increment without adding another catalog map; see the [toolchain guide](upstream-map-toolchain.md) for current aggregate counts. Complete callable/instantiation coverage, external declaration closure and CUDA compiler/runtime validation remain open.
