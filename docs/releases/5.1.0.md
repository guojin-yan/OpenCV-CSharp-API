# 5.1.0

Status: In development; not published / 状态：开发中，未发布

## Summary / 概要

The development target and managed/runtime package version move to OpenCV `5.1.0`, released upstream on 2026-11-06. Builds use the official matching tags: OpenCV commit `e4f78fbcf1a773fbed69e14500e8b734963eb585` and opencv_contrib commit `b67a855188a3d683813731010f6d39ac614733a4`. The unfinished 5.0.1 development work is carried forward into this version.

开发目标与 managed/runtime 包版本统一升级为上游于 2026-11-06 发布的 `5.1.0`。构建固定使用上述 OpenCV 与 opencv_contrib 正式标签对应提交，并承接原 5.0.1 尚未发布的开发内容。历史版本说明与证据继续保留。

## Managed API / 托管接口

- Build diagnostics and generated package metadata report `5.1.0`; the checked API baseline contains 647 public types, 7,010 public/protected members and 41 namespaces.
- `CalibrationFlags.DisableSchurComplement` is corrected to bit 27 (134217728). Its old value collided with `TiltedModel`, causing a five-coefficient calibration to select 14-coefficient tilted distortion. Recompile callers using the constant and explicitly migrate saved numeric flags; see [calibration 5.1 migration](../articles/calibration-5.1-migration.md).
- `BFMatcher.IsMaskSupported` follows OpenCV 5.1: false with CrossCheck enabled, true when it is disabled. The existing native property forwarding is retained.
- Existing TensorFlow importer overloads remain callable, but OpenCV 5.1 has removed that importer. Calls return an explicit `OpenCvException` with an ONNX conversion suggestion. TensorFlow Lite is a separate importer.
- ONNX-loaded networks now use the unified OpenCV engine and report `DnnModelFormat.Onnx`, including the classic-engine compatibility selection. Text graph dumps and inference work. PBTXT export is rejected explicitly before the incompatible upstream exporter can clear the loaded graph; inference remains usable after the rejected export.
- Preserve ABI 1 engine values by translating `Auto`/`Classic`/`New`/`Ort` to OpenCV 5.1's new internal enum values. Translate TFLite model-format diagnostics back to the stable managed value 3; it was incorrectly reported as TensorFlow before this correction. See [DNN 5.1 migration](../articles/dnn-5.1-migration.md).
- Inherited development work includes capability diagnostics, typed matrix access and bounded codec preflight. Sun Raster byte-RLE validation now handles 1/8/24/32-bit storage, padded rows and Int64 expansion counts without allocating an expanded image.

保留既有公开成员和包标识。TensorFlow 导入器在上游移除后返回明确错误，调用方应将模型转换为 ONNX；TensorFlow Lite 不属于此次移除范围。ONNX 格式诊断采用上游 5.1 的实际返回值。Sun Raster 修复保持头部事实与 native 解码、色彩语义和最终分配之间的独立边界。

## Native ABI and runtimes / Native ABI 与运行时

- Native ABI remains version 1 with 2,669 Full and 527 Mini entry points.
- Windows x64 Release OpenCV 5.1.0 and the Full wrapper compile from the fixed source commits. The Mini wrapper uses the six required modules from that same Full OpenCV installation; this is not a separately compiled minimal upstream tree.
- The [local Linux preview](../articles/linux-5.1-local-preview.md) builds Ubuntu 22.04 x64 Full (17 modules) and Mini (6 modules), verifies both ELF/ABI closures and passes independent package consumers on Ubuntu 22.04, Debian 12 and Fedora 44. The four new Debian/Fedora runs reuse the exact original packages and preserve the original Ubuntu record. Full/Mini CTest each pass 3/3. The actual 5.1 ELF SONAME is `.so.501`, distinct from Windows `510`; the shared consumer naming rule is corrected. All six local profile/distro pairs pass; the preview remains non-publishable.
- Linux producer/package workflows and the lifecycle-refresh producer calculate the ELF SONAME from the selected version. Local execution of the current generic ELF audit passes with the preserved Full/Mini 5.1 artifacts; both fail under the old `.so.500` expectation. Seven version cases, twelve invalid inputs and every affected name/dependency expression are checked. Hosted execution and additional architecture consumers remain pending.
- Twelve additional local package consumers cover Full/Mini on net8.0/net10.0 across Ubuntu 22.04, Debian 12 and Fedora 44. All write/read a three-frame MJPG AVI through `CV_MJPEG`, verify frame pixels and EOF, and roundtrip PNG pixels exactly. Six Full runs verify two named identity ONNX inferences each on the OpenCV CPU backend; six Mini runs verify the omitted DNN importer entry point. Managed/native bytes are bound to the existing SBOM/package manifests. This adds file-backed VideoIO and fixed-model inference evidence; device/network, other codecs/models and hosted coverage remain pending.
- The audited photo CCM patch remains necessary in 5.1.0 and stores the color-space value per model. Runtime-input provenance records the version-specific patch.
- The package matrix describes the packaging contract. Earlier multi-RID, support, performance and original 73-module catalog results were measured against OpenCV 5.0.0. All 73 historical parser scopes now record 5,778 current 5.1 declarations. The [backend and dependency review](../articles/opencv-5.1-backend-mapping.md) adds the final eighteen scopes and retains current Cudev/MATLAB lexical and CST inventories. The [public module review](../articles/opencv-5.1-public-module-mapping.md) adds nineteen scopes with 880 declarations, reviews ColoredKinFu optional color output and corrects the CVV Qt module gate. The [image and geometry review](../articles/opencv-5.1-image-geometry-mapping.md) adds fourteen scopes with 346 unchanged declarations. The [eight-scope contrib review](../articles/opencv-5.1-contrib-mapping.md) adds 611 declarations after the previous nine scopes added 1,300 declarations across Features, HighGui, ML, ObjDetect, Photo, Stitching, Tracking, Video and VideoIO; see [additional module mappings](../articles/opencv-5.1-module-mapping.md). The shared tool preserves exact before/after changes and decisions; zero historical parser maps remain pending; complete C++/template and runtime coverage remain separately scoped. See [5.1 source mapping](../articles/opencv-5.1-source-mapping.md) for unexposed tensor/alpha/font APIs, enum additions and managed input restrictions. These results do not establish complete C++ parity or optional backend/codec support.

当前真实构建覆盖 Windows x64、本地 Ubuntu 22.04 x64 与 Fedora 44 x64。Fedora Full/Mini 使用独立上游构建目录，分别编译既定17/6模块，通过全部2669/527项ABI与各3项CTest；独立Fedora容器在net8/net10执行四组新包还原、编译与PNG/MJPG/Full ONNX/Mini入口缺失验证。候选版本为`5.1.0-fedora44.b7f8180`；实际Fedora ELF符号要求独立记录，不外推通用glibc基线。此前Ubuntu包在Ubuntu22.04、Debian12、Fedora44的消费证据保留原包哈希。详见[Fedora源码与包证据](../articles/linux-5.1-local-preview.md#fedora-44-source-builds)。ARM64、hosted、Fedora完整第三方审查和正式发布证据继续逐项刷新，旧5.0.0多RID证据保留原测量版本。

## Compatibility and migration / 兼容与迁移

Use managed and runtime packages with the same version. Package IDs, namespaces, native library names and C entry point identities remain version neutral. TensorFlow `.pb`/`.pbtxt` models require conversion before loading in 5.1.0. ONNX format diagnostics may change from `Generic` to `Onnx`.

managed 与 runtime 应使用相同版本。CCM 实例状态补丁继续应用，避免一个模型选择 Adobe RGB 后改变其他 sRGB 模型。既有 5.0.0 发布审批例外不适用于新的 5.1.0 候选版本。

## Validation / 验证

The [5.1 performance baseline](../articles/performance-5.1-baseline.md) records twelve isolated codec/typed Mat/VideoIO/DNN harness runs and fourteen median metric groups against the exact local 43-DLL Windows x64 Full package. It initializes current-version regression thresholds, retains upstream unified-engine diagnostics and does not compare the different historical 5.0 runtime bytes. 5.1 性能证据独立绑定当前产物，旧 5.0 报告不作为跨版本无回归的证明。

The repository invariant suite includes the 15-TFM build matrix, 73 historical module semantic guards, the 5.1 DNN guard and the shared 5.1 refresh guard (2,420 mutations, plus 64 current source-semantic fixtures). Full and Mini native CTest each pass all three checks: native smoke, generated ABI consistency and actual DLL export audit. Managed regression checks use the newly built 5.1.0 Full DLLs with native execution enabled on net8.0 and net10.0 (2,090 passed per framework), including all four engine choices through ONNX/TFLite readers, TensorFlow removal, CCM isolation and codec preflight. The TFLite format regression failed for all four engines on the previous DLL and passes after conversion. Calibration regression reproduces 14 rather than five coefficients with the former Schur constant; all four solver/model combinations pass after correction. Both CrossCheck choices verify BFMatcher mask support. Build inputs, artifact hashes and actual results are recorded in [`opencv-5.1.0-source-build-evidence.json`](https://github.com/guojin-yan/OpenCV-CSharp-API/blob/opencv5.x/packaging/runtime/opencv-5.1.0-source-build-evidence.json).

仓库完整 invariant、15 个 TFM 构建、历史映射守卫和隔离预检测量用于验证迁移后的源码一致性；具体结果以本轮构建证据及 closeout 为准。5.1.0 尚未发布，正式候选包、SBOM、跨 RID 验证和发布授权仍待完成。
